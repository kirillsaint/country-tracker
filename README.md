# Country Counter

Личный трекер: в каких странах и городах я провожу время. iOS-приложение пишет точки
геолокации в фоне, бэкенд на TypeScript считает дни по странам, резидентство (183 дня)
и правило Шенгена 90/180.

```
backend/   Hono + MongoDB, Docker
ios/       SwiftUI, проект генерируется XcodeGen'ом
```

## Как это работает

Приложение **не** опрашивает GPS раз в час по таймеру — iOS такого не даёт. Вместо этого:

1. **Visit monitoring** — iOS сама сообщает «приехал в место / уехал». Почти не ест батарею.
2. **Significant location changes** — переезды на ~500 м+ / смена соты. Ловит смену города и страны.
3. **BGAppRefreshTask** раз в час (не гарантированно) — снимает одну точку как страховка.
4. При каждом открытии приложения — точка (защита от дребезга: не чаще раза в минуту); экран
   обновляется сразу из кэша сервера, а после отправки точки — ещё раз, уже с ней.

Точки копятся локально (`pending-points.json`) и уходят на сервер пачкой, когда есть сеть.
Сервер определяет страну по координатам оффлайн (`@rapideditor/country-coder`), город
приходит с устройства (`CLGeocoder`).

Статистика считается из сырых точек каждый раз заново. Точек мало (visit monitoring молчит,
пока стоишь на месте), поэтому дни между двумя соседними точками приписываются стране более
ранней точки. День с двумя странами засчитывается обеим — так работают правила резидентства.
Любой день можно поправить вручную (`PUT /api/days/:date`).

## Бэкенд

### Запуск через Docker

```bash
cp .env.example .env      # заполнить ALLOWED_EMAILS, при необходимости GOOGLE_CLIENT_IDS
docker compose up -d --build
curl localhost:3000/health
```

Данные Mongo живут в volume `mongo-data`. Порт API публикуется только на `127.0.0.1:3000` —
наружу смотрит nginx.

### Деплой: nginx + Cloudflare

Схема: iPhone → Cloudflare (HTTPS, сертификат Cloudflare) → nginx на сервере по HTTP →
Docker на `127.0.0.1:3000`.

```bash
# на сервере
git clone <repo> country-counter && cd country-counter
cp .env.example .env && nano .env            # ALLOWED_EMAILS, GOOGLE_CLIENT_IDS
docker compose up -d --build
curl localhost:3000/health                   # {"ok":true}

# nginx
sudo cp deploy/nginx/country-tracker.conf /etc/nginx/sites-available/
sudo ln -s /etc/nginx/sites-available/country-tracker.conf /etc/nginx/sites-enabled/
sudo sh deploy/nginx/update-cloudflare-ips.sh   # создаёт /etc/nginx/cloudflare-ips.conf и перезагружает nginx
```

В Cloudflare: A-запись `country-tracker` → IP сервера с включённым прокси (оранжевое облако);
SSL/TLS → Overview → **Flexible**. Проверка: `curl https://country-tracker.kirillsaint.ge/health`.

Обновление: `git pull && docker compose up -d --build`. Бэкап базы:
`docker compose exec mongo mongodump --archive --db country_counter > backup.archive`.

### Документы и основания въезда

Вкладка «Документы»: паспорта, визы, ВНЖ/ПМЖ (`/api/documents`). Номера документов не хранятся —
только страна, зона действия, сроки и параметры пребывания. Из визы и ВНЖ сервер собирает правила
автоматически (`documents.ts`): виза → «до N дней за въезд» (fromDate + autoStart) и/или «L в любые
W» (rolling), обе с `validUntil` = срок визы; ВНЖ → цель «≥ N дней в году» и правило типа `absence`
«не отсутствовать дольше N дней подряд». Правила помечены `documentId`/`documentRole` и пересобираются
при изменении документа. Если пользователь отредактировал автоправило руками (`customized: true`),
документ его больше не перезаписывает; `POST /api/rules/:id/reset` возвращает значения из документа.
Истёкшие по `validUntil` правила в `/stats/rules` не попадают.

В хронологии день перелёта показывается в обоих отрезках: отрезок страны, откуда уехали, дотягивается
до дня, где она есть, но уже не основная (`timeline()` в `stats.ts`); сумма дней за год считает такой
день один раз.

Однократная виза (`entries: single`) считается потраченной, если у неё стоит флаг `used` (ставится
руками в редакторе; сервер запоминает `usedAt` и закрывает её правила этой датой), либо — только на
клиенте — если по ней оформлено уже закончившееся пребывание или внутри срока действия есть ручная
запись о поездке в её страну. Такая виза показывается как «Использована · даты» вместо красного
«Истекла», и напоминаний об истечении по ней нет. Напоминания об истечении вообще не шлются за
прошлое: при первом запуске и для документов, добавленных уже просроченными, ступени (30 дней /
7 дней / истёк) просто отмечаются пройденными.

Срок паспорта: условие режима `passportValidity` получило поле `months` (сколько месяцев паспорт
должен действовать на въезде; помощник заполняет его из источников). На экране условий въезда
показывается, проходит ли ваш паспорт: по требованию страны, а без него — по общему порогу в 6 месяцев.
В списке документов паспорт с запасом меньше 6 месяцев подсвечен, а уведомления о паспорте приходят
за полгода, 30 дней, 7 дней и в день истечения.

Продление (`POST /api/documents/:id/renew {validFrom?, validTo}`) — кнопка «Продлить…» в редакторе визы
или ВНЖ: документ остаётся тем же (основания въезда и ручные правки правил не теряются), прежний срок
уходит в `history`, правила пересобираются под новые даты, флаг `used` сбрасывается.

Смена статуса без пересечения границы: запись основания с `kind: "switch"` и датой смены внутри
пребывания (в приложении — «Сменился статус во время пребывания…» в листе основания, а также
предложение сразу после сохранения ВНЖ на страну, где человек сейчас). `/stats/current` отдаёт
`entry` (въезд) и `switched` (последняя смена). Правила считают дни с учётом основания
(`buildBasisIndex` в `stats.ts`): правило безвиза (`regimeId`) не считает дни под ВНЖ, визой или
гражданством; правила визы (`documentRole` stay/window) — дни под другой визой, ВНЖ, безвизом или
гражданством; дни без основания считаются везде. Основание действует до следующей записи в том же
непрерывном пребывании и не переносится на следующее.

Основание въезда (`/api/entries`) — «страна + дата въезда → гражданин / безвиз / виза / ВНЖ / транзит /
другое + документ». Задаётся тапом по отрезку в истории; в хронологии показывается бейджем.
Напоминания об истечении документов — локальные, за 30 и 7 дней и в день истечения.

### Режимы въезда (безвиз) и помощник

`regimes.ts`, `ai.ts`. Режим = пара «паспорт → страна» с **набором ограничений** (у Турции для РФ их
два: 60 дней за въезд и 90 в любые 180), чек-листом условий (регистрация в течение N дней, срок
паспорта, страховка), источниками и **версиями**: при изменении условий активная версия закрывается
сегодняшним днём и уходит в `history`, её правила выключаются с `validUntil`, новые получают
`validFrom`. Эти даты — запись о том, какая версия когда действовала (история показывает у прошлых
поездок «правила тогда»); на подсчёт они не влияют: активные правила считают все фактические дни,
смена условий не обнуляет уже проведённое время в окне. Правила режима помечены
`regimeId`/`constraintId`; ручная правка закрепляет их (`customized`).

Заполнение — вручную (шаблоны «N за въезд / N в любые M / N в год / N с даты») или кнопкой
**«Заполнить автоматически»**: `POST /api/regimes/:passportId/:country/check` запускает фоновую
задачу — запрос к OpenRouter (`OPENROUTER_MODEL`, по умолчанию `openai/gpt-5.6-sol`, плагин
веб-поиска `web`, structured output по JSON-схеме). Модель ищет официальные источники и возвращает
черновик: требование, ограничения в нашей терминологии, условия, ссылки с пометкой official,
резюме, дату актуальности, уверенность. Черновик **никогда не применяется сам** — пользователь
проверяет и подтверждает (`PUT /api/regimes/...`, `origin: "ai"`). Готовые проверки кэшируются
по паре на `REGIME_FRESH_DAYS` (30) дней и общие для всех пользователей; приложение опрашивает
`GET /api/regime-checks/:id` пока открыт экран и при каждом обновлении данных (в т.ч. фоновом),
после чего показывает уведомление «Условия въезда: Турция — найдено …». Без ключа помощник
выключен, ручной ввод работает.

Перепроверка: в `/stats/current` есть `regime.stale` (последняя проверка старше 30 дней или её
не было). Тогда в вопросе «как въехали?» кнопка безвиза становится «Безвиз 🇷🇺 · проверить условия»
и сразу запускает поиск; в приложении — переключатель в листе основания. Результат сравнивается с
активной версией (`diff`: добавлено/убрано), пользователь либо применяет изменения (новая версия),
либо «оставляет моё», либо отмечает «проверено» без изменений.

### Вопрос «как въехали?»

`/stats/current` возвращает `entry` (основание текущего пребывания), `previousEntry` (последнее
основание для этой же страны — «как в прошлый раз») и `entryPending`. Страна своего паспорта
помечается основанием `citizen` автоматически. Приложение при `entryPending` показывает локальное
уведомление с кнопками (до четырёх: «как в прошлый раз» / безвиз по паспорту / ВНЖ / виза /
транзит / другое; `EntryPrompter.swift`) и баннер на главном экране — один раз на (страна, дата
въезда). Ответ кнопкой сохраняет основание и для безвиза создаёт правило по справочнику. Проверка
идёт и в фоне после отправки точек, поэтому вопрос приходит вскоре после прилёта.

### Правила подсчёта

Вместо зашитых «183 дня» и «90/180» — произвольные правила:

- `type`: `calendarYear` (1 января – 31 декабря), `rolling` (любые `windowDays` подряд, окно
  заканчивается сегодня), `fromDate` (с `startDate` на `windowDays` дней или бессрочно),
  `absence` (дней подряд вне стран правила — обязательство ВНЖ);
- `autoStart` (только `fromDate`): дата начала определяется по данным — первый день текущего
  непрерывного пребывания в странах правила. Выехал и вернулся — отсчёт с нуля. Так работает,
  например, безвиз Грузии для россиян (365 дней с въезда). Ответ содержит найденную `entryDate`;
- `mode`: `limit` — нельзя превышать (визы), `goal` — нужно набрать (резидентство);
- `countries`: список ISO-кодов, пусто — любая страна;
- `countMode`: `any` — день считается при любом заходе в страну, `primary` — только если это
  основная (последняя) страна дня;
- `warnRemainingDays` / `notify` — порог предупреждения и уведомления.

Для `limit`-правил сервер считает `canStayDays` — сколько дней подряд, начиная с завтра,
можно оставаться, не нарушив правило (для скользящего окна — с учётом того, какие дни из
окна выпадут). Уведомления локальные: приложение проверяет результаты после каждого
обновления статистики и после фоновой отправки точек.

Если вход через Google c тем же подтверждённым email, что и у существующего Apple-аккаунта,
провайдер привязывается к нему автоматически (`autoLinked: true`) — второй аккаунт не создаётся.
Apple «Скрыть e-mail» даёт relay-адрес, он не совпадёт — тогда привязка руками из настроек.

### История и статистика

«История» показывает хронологию за все годы, сгруппированную по годам (отрезок через Новый год
режется на две части), с фильтром «все годы / конкретный год» — он же применяется к списку
городов. «Статистика» — срез за выбранный год или за всё время: дни, страны, города, поездки,
рейтинг стран и городов с долей от учтённых дней, самое долгое пребывание, где год начался и
закончился. Всё считается теми же эндпоинтами с параметрами `from`/`to`; список доступных лет
приложение выводит из хронологии.

### Карта

Вкладка «Карта» — плоская карта мира в духе Been: посещённые страны закрашены (насыщеннее там,
где больше дней), в режиме «Города» — точки городов (координаты — среднее по точкам с этим
городом, у ручных записей их нет). Границы — Natural Earth 1:50m, упакованы в
`CountryCounter/Resources/world.json` (~1.3 МБ, 236 стран, есть даже Мальта и Сингапур; совсем
мелкие страны рисуются маркером). Рисуется через `Canvas`, зум — щипком, двойной тап и
«Сбросить масштаб» подгоняют вид под посещённые места. Экспорт в PNG (2400 px, светлая
палитра, заголовок и подпись) — кнопка «Поделиться» → системный share (Фото, Файлы, мессенджеры).

Пересобрать `world.json` из свежих данных Natural Earth: скрипт в истории проекта тривиален —
GeoJSON `ne_50m_admin_0_countries` → код `ISO_A2_EH`, координаты округлены до 0.01°, без Антарктиды.

### Виджеты

Расширение `CountryCounterWidgets` (домашний экран и экран блокировки):

- **Now / Сейчас** — маленький (флаг, страна, город, дней подряд), средний (плюс до трёх правил
  с прогрессом), inline / rectangular / circular для экрана блокировки.
- **Rule / Правило** — кольцо прогресса по одному правилу, правило выбирается при настройке
  виджета (можно поставить несколько). Small, circular, rectangular, inline.

Данные: приложение после каждого обновления статистики пишет `widget-snapshot.json` в контейнер
App Group `group.ge.kirillsaint.stamps.shared` и дёргает `WidgetCenter.reloadAllTimelines()`.
Виджет читает снимок и сам добавляет прошедшие сутки к «дней подряд / в этом году»; правила не
экстраполирует (неизвестно, в стране ли человек) — их обновит приложение, когда проснётся в фоне.
App Group прописан в обоих вариантах entitlements приложения и у виджета.

### «Чем заняться» — рекомендации мест

Раздел на главной вместо списка стран: категория (поесть, кофе, погулять, культура, вечером, с детьми,
шопинг, дождливый день, «удиви меня») или свободный запрос, рядом с собой или в любом городе из
справочника. Два слоя: **Google Places API (New)** даёт кандидатов с фактами (`places.ts`: nearby /
text search, детали, фото), **нейросеть** через OpenRouter выбирает 6–8 из них под запрос, время суток,
«открыто сейчас» и профиль вкусов и пишет по одному предложению «почему вам» (`discover.ts`). Модель
видит только id кандидатов — придумать место не может; чужие id отбрасываются. Без ключа OpenRouter —
сортировка по рейтингу с байесовской поправкой на число отзывов.

Данные Google кэшируются сутки (`place_cache`, TTL-индекс; лимит лицензии 30 дней), координаты
округляются до ~100 м. Фото не хранятся: приложение получает подписанную ссылку на наш прокси
`GET /api/places/photo?name&w&exp&sig` (HMAC от ключа, без сессии — AsyncImage не умеет заголовки),
прокси редиректит на картинку Google; рядом с фото показывается автор (условие Google).

Оценки (`PUT /api/places/:id/rating`): звёзды 1–5 обязательно, по типу места необязательные параметры
1–5 (еда/сервис/цена/тишина; кофе/атмосфера/удобно работать; виды/толпа; интересно; детям…), теги,
«пошёл бы снова», заметка, дата. Сохранённые (`/api/places/:id/save`), «не интересно» (`/dismiss`) —
такие места в подборки не попадают, как и оценённые ниже трёх. Профиль вкусов (`taste_profiles`) —
2–3 абзаца, которые модель переписывает, когда прибавилось ≥3 оценки, и получает в промпт. Каждая выдача
логируется (`discover_log`: что показали) для будущей оценки качества.

Погода (`weather.ts`, Open-Meteo без ключа: «сейчас» с кэшем 30 мин, для маршрута на другой день —
почасовой прогноз на час старта до 16 суток вперёд, кэш 3 ч) идёт в промпт: в дождь, жару (≥35°) и мороз
подборка «удиви меня» берёт закрытые места, а модель это объясняет; приложение показывает погоду на экране
поиска. В промпт также уходят последние 20 оценок пользователя с названиями — объяснения вида
«похоже на Roasters, которому вы поставили 5». Маршрут на полдня (`POST /api/itinerary {lat, lon, hours,
startTime}`): кандидаты из четырёх категорий (кофе, прогулка/помещения по погоде, культура, еда), модель
выбирает 3–4 остановки в логичном порядке со временем. Поле `note` — пожелания («обязательно зайти в
Roasters, ужин у воды»): названные места ищутся текстовым поиском и добавляются в кандидаты с меткой
`mentioned-by-user`, промпт требует включить их в маршрут; сохранённые места в двойном радиусе тоже
попадают в кандидаты с меткой `saved`. В приложении экран «Маршрут на полдня» с открытием
всего маршрута в Google Maps (Apple Maps ведёт только к одной точке). Уведомление «рядом сохранённое
место» приходит, когда любая точка оказалась в 300 м от сохранённого, не чаще раза в 3 дня на место.

Подборка и маршрут выполняются как задачи (`jobs.ts`): `POST /api/discover` и `POST /api/itinerary`
сразу отвечают `202 {jobId}`, работа идёт в фоне процесса, приложение опрашивает `GET /api/jobs/:id`
раз в 2 секунды (статусы queued/running/done/failed, результат хранится час, TTL-индекс). Так ответ
нейросети в 15–60 с не упирается в 20-секундный таймаут клиента, а если свернуть приложение, опрос
продолжится после возврата. `sync: true` в теле — дождаться результата в том же запросе (для curl).
При перезапуске сервера незавершённые задачи помечаются `failed`.

Мини-тест о вкусах (`GET/PUT /api/taste`, коллекция `taste_preferences`): кухни, приоритеты, атмосфера,
бюджет, компания, ограничения в еде, чего избегать, известное/скрытое, свободная заметка. Ответы уходят
в промпт как «Stated preferences» и работают с первого поиска, пока оценок ещё нет; после сохранения
локальный кэш автоподборки сбрасывается. В приложении — баннер на экране поиска, пока тест не пройден,
и пункт «Ваш вкус» в меню экрана.

Вопрос «как вам?» приходит уведомлением сам: мониторинг визитов iOS замечает, что вы провели ≥25 минут
в 120 м от рекомендованного или сохранённого места (`PlaceVisits.swift`), тап открывает экран оценки.

Настройка: `GOOGLE_PLACES_API_KEY` в `.env` (Places API (New), ключ ограничить этим API), `PUBLIC_BASE_URL`
для ссылок на фото за прокси (в докере — прод по умолчанию). Отладка в симуляторе:
`-debugDiscover eat` (открыть экран и запустить поиск), `-debugDiscoverHome walk` (подборка на главной);
местоположение — `xcrun simctl location <udid> set 25.08,55.14`.

### Локализация

Города хранятся по-английски: геокодер на устройстве всегда вызывается с `en_US`, а город из ручной
записи приводится к английскому написанию через прямое геокодирование (`CityNames.canonicalEnglish`),
чтобы «Дубай» и «Dubai» были одной строкой статистики. Показываются города на языке приложения:
`CityNames` (iOS) спрашивает у геокодера перевод по одному разу на город и кэширует его в UserDefaults;
пока перевода нет, видно английское имя. Главный источник переводов — сервер: при первом старте он
потоком (HTTP Range + inflate, без скачивания архива целиком) читает GeoNames `alternateNamesV2` и
кладёт в справочник `cities` поле `i18n` для языков из `CITY_LANGS` (по умолчанию `ru`; берётся
предпочтительное имя, затем обычное, разговорные и исторические — в последнюю очередь). Приложение при
каждом обновлении данных забирает `GET /api/city-names?lang=ru` — переводы городов из своей истории — и
они перекрывают локальный кэш; поиск `GET /api/cities?…&lang=ru` тоже отдаёт `localized`. Геокодер
остаётся только запасным вариантом для городов, которых нет в справочнике, и наружу его результат не
уходит: пользовательский ввод в словарь не попадает. Сервер группирует города без учёта регистра и пробелов.
Город в ручной записи не вводится руками, а выбирается из справочника **GeoNames cities5000**
(все населённые пункты от 5 000 жителей, ~70 тысяч, лицензия CC BY 4.0, атрибуция в подвале экрана
выбора). Сервер скачивает его сам при первом старте с пустой коллекцией `cities` (~3 МБ с
download.geonames.org, нужен исходящий интернет у контейнера; `CITIES_REIMPORT=1` — пересобрать) и
хранит с полем `search` — все написания из GeoNames в нижнем регистре, поэтому «стам» находит Istanbul.
Сохраняется английское имя; для городов только из ручных записей координаты на карте берутся оттуда же.
Старые записи с городами не латиницей приложение чинит само: после обновления данных находит такие
города в истории, узнаёт английское имя у геокодера и вызывает `POST /api/cities/rename
{countryCode, from, to}`, который переименовывает город в точках (исходное имя остаётся в `cityRaw`)
и ручных правках. Каждый город проверяется один раз (список в UserDefaults).

Английский (исходный) и русский. Все строки — английские ключи в коде, переводы в
`CountryCounter/Localizable.xcstrings` (String Catalog, редактируется в Xcode). Новую строку
достаточно написать в коде по-английски и добавить русский вариант в каталог. Язык приложения
следует языку iPhone; переопределить можно в Настройках iOS → Country Counter → Язык.
Названия стран (`Locale.localizedString(forRegionCode:)`), даты и склонения («1 день / 2 дня /
5 дней») идут из системной локали и каталога, серверу язык не нужен.
